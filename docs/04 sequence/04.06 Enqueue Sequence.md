## Asynchronous Flow Details ##

| Phase | Description |
|---|---|
| **Enqueue** | Synchronous — player clicks Enqueue, gets immediate confirmation with queue position. Dashboard remains interactive. |
| **Matchmaking** | Asynchronous — `MatchmakingService` runs in the background. When enough players are matched, it creates a session via `GameSessionManager` and publishes a `MatchReady` event. |
| **Notification** | Asynchronous — GUI subscribes to `MatchReady` events on the `EventBus`. When the event arrives, a notification modal/toast is displayed to the player. Player can accept or decline. |

## EventBus Events ##

| Event | Publisher | Subscriber | Payload |
|---|---|---|---|
| `MatchReady` | MatchmakingService | GUI (DashboardView) | `{sessionId, playerIds, gameType}` |
| `QueueUpdate` | MatchmakingService | GUI (DashboardView) | `{playerId, newPosition, estimatedWait}` |
| `MatchDeclined` | MatchmakingService | GUI (DashboardView) | `{playerId, returnedToQueue: boolean}` |

## Integration with Other Use Cases ##

| Use Case | Relationship |
|---|---|
| **UC-04: View Dashboard** | Player returns to dashboard after enqueueing; dashboard displays queue status badge. |
| **UC-08: Join Game** | When player accepts match notification, flow transitions to UC-08 Join Game sequence. |
